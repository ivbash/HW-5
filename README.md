# ДЗ №5. Хуки и формы

## Вопросы для самопроверки

### 1. Чем useCallback отличается от useMemo? Когда использовать каждый?

Хук `useMemo` предназначен для мемоизации тяжелых вычислений, в него передается функция, возвращающая результат вычислений. `useCallback` принимает функцию, которую нужно мемоизировать.

`useCallback` работает в связке с `React.memo` для оптимизации перерисовки компонента.

### 2. Почему React.memo не помогает, если колбэк передаётся без useCallback?

Когда мы оборачиваем компонент в `memo`, перед его рендером происходит простое сравнение пропсов с ранее переданными (`prevProps.onClick === nextProps.onClick`). При рендере компонента функция создается каждый раз заново (соответственно меняется ссылка), поэтому нужно ее оборачивать в `useCallback`.

### 3. Когда стоит использовать useReducer вместо useState? По какому признаку вы принимаете это решение?

`useReducer` стоит использовать, когда у нас есть сложная логика изменения состояния.

Например, состояние - сложный объект, менять нужно только часть состояния, изменение одной части затрагивает другую, а мутировать объекты нельзя, нужно создавать новые. Поэтому логику изменения состояния лучше вынести в отдельную функцию `reducer`.

### 4. Что такое useRef и почему изменение .current не вызывает ре-рендер?

`useRef` возвращает объект со свойством `current`, куда можно записать какие-либо данные и изменять их без вызова ре-рендера. Также, можно передать этот объект в `ref` DOM-элемента для получения его ссылки.

Так как `useRef` возвращает обычный объект, свойство `current` мы можем изменять напрямую, поэтому ре-рендер не вызывается.

### 5. Зачем useContext нужен провайдер (Provider)? Что произойдёт, если использовать useContext вне провайдера?

В провайдер мы передаем текущее состояние, которое будет возвращать `useContext`. Вне провайдера `useContext` вернет состояние по умолчанию, с которым был создан контекст. Как-то изменить состояние без провайдера мы не можем.

### 6. В чём разница между controlled и uncontrolled инпутом? Как React Hook Form использует uncontrolled подход?

Контролируемый инпут принимает значение `value` (или `checked`), т. е. состояние хранится вне DOM-элемента (например, `useState`). Как правило, нужен обработчик `onChange` для изменения состояния инпута. Ре-рендер компонента происходит на каждое изменение значения инпута.

В неконтролируемый компонент значение не передается, а получить его можно через `ref`. DOM-элемент сам хранит свое значение. Ре-рендера не происходит при изменении инпута.

React Hook Form использует `useRef` для работы с инпутами, что позволяет не совершать лишние перерисовки компонентов формы, когда изменение одного поля вызывают ре-рендер всей формы.

### 7. Почему zodResolver — это не валидация на сервере? Где ещё нужно валидировать данные?

`zodResolver` используется для валидации схемы `zod` в React Hook Form. Это валидация формы на стороне клиента, чтобы сразу вывести пользователю ошибки при заполнении формы до ее отправки.

Валидация данных обязательно нужна на сервере, так как все данные, пришедшие извне, нужно проверять. Можно использовать ту же схему `zod`, что и на клиенте.
